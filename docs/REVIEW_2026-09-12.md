## Correctness findings and fixes

| Finding | Change | Regression evidence |
|---|---|---|
| A harmless first occurrence hid a later demand for the same pattern | Gate every sentence before pattern deduplication | Earlier payment question followed by an explicit demand, with concepts on/off |
| Quotes were mapped back to speakers using text search | Carry sentence ownership directly into each match | Identical tenant/landlord wording; long excerpts retain the correct owner |
| The last question changed the speech act of an entire message | Determine speech act for the quoted sentence | Payment demand followed by a separate ordinary question |
| Short role aliases matched inside personal names | Require exact aliases or bounded descriptive role labels | Minji, Alice, Hana, Jimin and Sam remain unknown; explicit role labels still work |
| Polite payment demands were treated as harmless questions | Allow explicit payment requests through the question gate for payment patterns | Korean/English demands versus document questions and tenant requests |
| A question mentioning consent suppressed a trust warning | Limit cross-message reassurance to counterparty statements and preserve explicit conflicting clauses | Consent question or delayed consent cannot erase a trust-property warning |
| One common pre-viewing payment phrasing was missed | Add a narrow three-term combination and specific no-payment controls | Required pre-viewing payment versus no need to pay and a risky negative conditional |

These changes improve the tested cases. The analyzer still uses curated rules,
not a trained classifier. It can miss paraphrases, sarcasm, context and ambiguous
speaker roles. Human review of recognized text and evidence remains necessary.

## Additional screenshots and independent expectations

`assets/examples/cases.json` defines 12 fictional conversations before OCR,
their teaching category, intended assessment, required rule IDs and KO/EN
explanations. The images contain explicit role labels and no real identifiers.
Three use dark chat backgrounds. They supplement the existing 22 demo fixtures.

| Category | Cases | Intended behavior |
|---|---|---|
| Ordinary | Documents available; tenant refusal; landlord denies payment pressure | No known signals, which does not mean verified safe |
| Careful/uncertain | Too little information; pushed substitute room; reported registration restriction | Insufficient information or needs review |
| Pressure | Polite immediate payment; later demand after a harmless question; payment before viewing | Strong warning signals with quoted evidence |
| Strong risk indicators | Third-party payment; registration restriction; trust consent delayed | Strong warning signals requiring independent verification |

`assets/examples/observations.json` stores image hashes, browser version, actual
OCR drafts, uncorrected assessments, correction flags and reviewed results.
In the recorded Chromium 153.0.8010.12 run, all 12 reached the independently
specified assessment and required findings without text corrections. Some OCR
headings/footers contain errors. This is not perfect OCR, a real-phone study,
or an accuracy percentage. The regression tests must not replace failed targets
with whatever the analyzer happens to return.

Reproduce with the locked dependencies and installed Playwright Chromium:

```sh
npm run assets:stamp
npm run build
npm run test:learning
```

To intentionally regenerate images, run `python scripts/make-learning-screenshots.py`
with Pillow and a Korean font (`EXAMPLE_FONT` can override the Windows default).
Then build and run `node scripts/smoke-learning.mjs --record`. Inspect all raw
drafts, corrections and independent targets before committing observations.

## Interface and model clarification

- The report reads top to bottom: 1 summary, 2 coverage, 3 evidence, 4 next
  checks, 5 reviewed export, 6 optional AI. Evidence highlights and action
  accents help readers locate the reason and next step.
- The AI panel separates opt-in, model loading and generation. It shows the
  actual source: downloaded bytes, verified browser cache or a selected GGUF.
  The model runs locally from those bytes on the visitor's CPU. Opt-in alone
  downloads nothing. Browser eviction or a different origin can require loading
  the file again. GitHub Pages and Vercel serve files; they do not run inference.
- The generation button references a visible wait warning. The measured desktop
  took 24-62 seconds; another laptop may take minutes or fail. Busy status repeats
  the warning and Cancel remains available. No new model benchmark is claimed.
- `help.html` offers bilingual independent checks, official-source links,
  category filters, downloadable examples and transcripts. A failed examples
  request offers Retry while the static guidance remains readable.
- Theme controls persist a light/dark preference across checker, Demo and help.
  They do not store the conversation or trigger model downloads.

## Release verification and limits

The release commands are `npm run verify:install`: unit/data suites during
build, real OCR, browser lifecycle and host checks, mocked LLM integration,
original demo examples, the 12 new screenshots and report consistency checks.
New UI checks cover 320, 390 and 1120 pixel widths, theme persistence, numbered
section order and the generation warning. Mocked model tests check integration,
not explanation quality. The model weights and inference configuration did not
change, so prior measured costs and quality limitations remain applicable.

GitHub Actions publishes only the validated public artifact. Check the workflow
and live GitHub Pages site before claiming publication. Existing Vercel support
remains optional; no Vercel deployment is claimed.
